API key security

Models

Media

Audio generation can reuse the Gemini API key above for Google Lyria music and Gemini speech. Add ElevenLabs here for ElevenLabs music and sound effects. Media keys follow the same session-only or encrypted-vault security rules as model keys.

Custom / BYOK

Four OpenAI-compatible connectors for smaller providers or local infrastructure. Enter a base URL such as http://localhost:1234/v1. API keys are optional. M+ will validate models through /models when available; a manually entered model is labelled as manual rather than validated.

Roles

Independent reviewers · up to 12
Choose a specific model for each reviewer slot. Built-in providers only offer models validated by the current API key. Custom/BYOK connectors also allow an explicitly labelled manual model when /models discovery is unavailable. Duplicate models are allowed and run independently. Reviewers are competitors: they challenge the Main, demand evidence and propose stronger alternatives.
Team persistence: this project keeps its own Main/reviewer structure. Saving from the Roles tab also makes the current structure the default for future projects.
Image generation
The Main still owns the visual brief and revisions. The selected generator is only the rendering engine. Automatic tries connected image-capable providers in order and falls back if one is unavailable. M+ maps aspect ratio, resolution and quality to the nearest option supported by each provider; unsupported controls are carried into the prompt rather than silently discarded.
Audio generation
The Main owns the audio brief. Automatic chooses a compatible connected renderer for music, sound effects or speech. ElevenLabs handles music and sound effects. Google uses Lyria 3 for music and Gemini TTS for speech. Duration, instrumental, loop and voice settings override the Main only when explicitly selected. Audio review currently uses configured Gemini reviewer slots because M+ does not claim unsupported reviewers can inspect sound.

Project storage

Shared workspace is for team collaboration. It lets several people open the same M+ project from different computers and work against the same chats, files, checkpoints and verification history instead of passing project copies back and forth. It requires an M+ Sync API v1 endpoint with CORS enabled. AI-provider API keys and the shared access token are never written into project data; the access token is retained only for the current browser session.

M+ Sync API v1 contract
GET /v1/workspaces/{workspace} - handshake and capabilities
GET /v1/workspaces/{workspace}/projects
GET|PUT|DELETE /v1/workspaces/{workspace}/projects/{id}
GET|PUT|DELETE /v1/workspaces/{workspace}/attachments/{id}
POST|DELETE /v1/workspaces/{workspace}/locks/{projectId}

Project PUT uses If-Match/revision values; conflicts return HTTP 409 with the current project. Workspace locks return HTTP 423 when another client owns the lock. Attachment PUT bodies are raw bytes with M+ metadata headers. The handshake must identify mplus-sync-v1.
